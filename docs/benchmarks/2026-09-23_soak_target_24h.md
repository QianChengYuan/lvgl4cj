# 长跑证据：目标形态硬件上连续运行 24 小时（2026-09-23）

本文记录**目标形态硬件上的长跑结果**。它回答的是"短跑通过"之外的那个问题：
连续跑很久之后，句柄、对象、动画上下文与内存会不会漂移。

原始产物随文一起入库（`docs/benchmarks/2026-09-23_soak_target_24h/`），可逐行复核：

| 文件 | 内容 |
| --- | --- |
| `soak_launch.log` | 启动记录、退出码、RSS 汇总（由 `test/native/target_soak.sh` 生成） |
| `soak_rss.csv` | RSS 全程采样，**1440 个样本**（每 60 秒一个，覆盖整 24 小时） |
| `soak_stdout.log` | 被测进程全部输出（1465 行，含 1439 条周期性进度行） |

## 一、结论

| 判据 | 结果 |
| --- | --- |
| 运行时长 | **86400 秒**（= 24 小时整；2026-09-22 21:47:17 → 2026-09-23 21:47:37） |
| 退出 | **退出码 0**，走完完整收尾流程（反初始化 headless 后端 → 反初始化运行时） |
| 负载总量 | **157,481,432 步**确定性序列（seed 20260921） |
| 检查项 | **10 项检查，0 项失败** |
| 稳态计数 | 末态归位：`alive 2→2`、`obj 6→6`、`anim_ctx=0`（无句柄/对象泄漏） |
| 有界回收 | `INVALIDATED` 保留量 **878**，未超过上限 1024 —— 1.57 亿步之后仍未越界 |
| 内存（RSS） | 最小 2616 KB（t=0）· 最大 **4796 KB（t=60 秒，预热峰值）** · 末值 3264 KB |
| 内存趋势 | 分段均值 **前 1/4 = 3408 KB → 中段 = 3264 KB → 后 1/4 = 3264 KB**（平台，非单调上升） |
| 泄漏迹象 | 后 1/4 段内刷新历史最大值的次数 = **1**（真泄漏会持续刷新） |

**内存那条为什么这样判**：启动脚本自己就写了判据 ——
「短跑内的小幅上升不构成结论，需要看整条曲线是否在振荡后回到同一水平」。
本次峰值出现在**第 60 秒**（预热），此后 24 小时再未超过它，末段与中段均值同为 3264 KB。

## 二、环境与运行方式

| 项 | 值 |
| --- | --- |
| 设备 | Raspberry Pi Zero 2 W Rev 1.0（4×Cortex-A53 @1GHz，**415MB 内存**） |
| 系统 | Debian GNU/Linux 13 (trixie)，内核 6.18.50+rpt-rpi-v8 |
| 被测二进制 | `test_soak_asan`（**ASan 构建**，即带 AddressSanitizer 的版本） |
| 显示后端 | headless（`SDL_VIDEODRIVER=dummy`，无窗口） |
| 启动方式 | `nohup` 后台 + 结果写文件（`test/native/target_soak.sh`），断线不影响测试 |
| 时长参数 | 86400 秒（恰好 24 小时，按参数跑满后**正常退出**，不是被外部掐断） |

复现（在目标机上）：

```sh
cd ~/lvgl4cj-target/bin
bash target_soak.sh 86400        # 时长单位秒；结果落 soak_launch.log / soak_rss.csv / soak_stdout.log
```

## 三、这份证据**不能**外推到什么（重要）

1. **只是一轮**。单次 24 小时通过是实质证据，但不等于"长期稳定"的统计结论 ——
   偶发问题需要多轮或更长时间才能暴露。
2. **RSS 每分钟采一次**。它能证明"没有分钟级的单调泄漏趋势"，
   但**证不了**秒级抖动，也证不了别的资源（fd、线程、GPU 内存）——本次没有采这些。
3. **ASan 构建比 Release 慢**。它证明的是"在 ASan 的地址检查下 1.57 亿步无报告"，
   不能当作 Release 的性能数据（性能结论在 `2026-09-22_perf_target_pizero2w.txt`）。
4. **负载是确定性序列，不是真实交互**。它覆盖了 label 文本路径、anim_ctx 生命周期、
   样式引用守卫拒绝释放等路径（见 `soak_stdout.log` 的"驱动覆盖"段），
   但不等于有人真的在点屏幕。
5. **有干扰，必须说明**：长跑的**最后一分钟**（21:47:17–21:47:37）里，
   宿主机的图形会话被停止过（为 KMSDRM 实测腾出 DRM master）。
   长跑本身是 `nohup` + dummy 驱动，未受影响（退出码 0、末态归位）；
   但严格来说，这一轮**不能**声称"全程无外部干扰"。

## 四、这次长跑顺带确认的一件事

它证明了"后台长跑"与"前台做显示实验"在目标机上是**可以并存**的：
长跑用 dummy 驱动、不碰 DRM，因此停/起桌面（`lightdm` + `labwc`）不会干扰它。
后续在目标机上做 kmsdrm 实测时，不必等长跑结束。
